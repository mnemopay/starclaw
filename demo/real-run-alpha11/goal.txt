The repository in ./mnemopay-sdk is the @mnemopay/sdk TypeScript package. Known bug: verifyBundle() in mnemopay-sdk/src/governance/audit-chain.ts accepts a tampered bundle in which the last event has been duplicated (appended a second time) when the original event count is odd. The cause is that the Merkle tree pads an odd layer by repeating the last leaf, so the duplicate produces the same root. The project's own docs admit this: "verifyBundle catches edits and deletions. It does not catch a duplicated last event."

Fix it with the smallest safe change. Every ChainEvent has a numeric `sequence` field and AuditChain assigns consecutive sequence numbers. Valid bundles must keep verifying exactly as before, and the way the Merkle root is computed must not change (roots have been anchored on-chain). Also add a vitest test to mnemopay-sdk/tests/audit-chain.test.ts that shows a duplicated-last-event bundle is now rejected while the untampered bundle still verifies. Read the existing source and test file first so the test uses the real API, then write the two changed files back to the workspace.
