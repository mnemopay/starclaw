Command reference

This list is taken from src/cli.ts and the bin entries in package.json at version 2.0.0-alpha.13 (published on npm as latest and next). Run starclaw --help for the authoritative list on your install.

Most commands also accept --policy, --state-dir, --workspace, --sandbox auto|container|process and --require-container.

CommandWhat it does
starclaw run <goal>Run one goal and exit. Options: --non-interactive (nothing is approved, so everything the policy does not auto-allow is denied), --json.
starclaw appThe console in your browser, on 127.0.0.1 only: a chat with live progress, approvals in the conversation, and searchable history. Opens already holding its key. On first run (or with --setup) it opens guided model setup: finds Ollama or LM Studio on this computer, or takes a Groq, Anthropic, OpenAI or OpenRouter key, and tests the model before saving. Options: --home, --port, --no-open.
starclawInteractive session (the default). In-session commands: /new (fresh session, clears taint), /status, exit.
starclaw policy init [file]Write the conservative default policy (default file starclaw.policy.json). Refuses to overwrite.
starclaw policy check [file]Validate a policy file. Exit code 1 if invalid.
starclaw doctorProbe the isolation layers on this machine and report what is blocked, which layer is active and why. Also reports model, search, browser and channel configuration (names and set / NOT set only).
starclaw audit verify <file>Check an audit log offline: hash chain, signatures and head checkpoint. Options: --pubkey, --pubkey-file, --allow-missing-head, --json. Pin the public key; without it the key inside the log is trusted.
starclaw audit export <file> --out <dir>Verify the log, then write an EU AI Act Article 12 bundle in MnemoPay’s format. Refuses a log that does not verify, and never overwrites existing bundle files. Options: --pubkey, --pubkey-file, --operator, --retention-months (6 or more), --budget-usd.
starclaw sandbox build | status | cleanBuild the Docker sandbox image, show Docker and image state, or remove leftover sandbox containers (only those labelled starclaw.sandbox=1).
starclaw shell build | status | cleanSame three actions for the governed shell container used by tools.shell.
starclaw schedule add | list | remove | pause | resumeManage unattended jobs. add <name> <schedule> <goal> takes a 5-field cron expression or @every 30m; options --heartbeat and --notify. Jobs run only while the daemon runs.
starclaw daemonLong-running process: Telegram gateway, the Slack, Discord, WhatsApp, Signal and email channels when enabled in the policy, and the scheduler. --no-telegram runs without Telegram.
starclaw slack statusCheck the Slack policy block and environment. Prints variable names and set / NOT set, never values.
starclaw discord statusSame check for Discord.
starclaw discord register [--guild <id>]Register the /starclaw slash command with Discord, globally or in one server.
starclaw skills keys add | list | removeThe keyring of publisher keys you trust. Only skills signed by a pinned key can ever install or run.
starclaw skills keygen | signPublisher side: create a signing key, and sign a skill folder into a .starclaw-skill bundle.
starclaw skills verify | install <file>Check a bundle, or install it. Installing always asks you, showing the publisher, version, requested capabilities and a diff.
starclaw skills list | revokeInstalled registry skills and whether each would run now; revoke one (or one version).
starclaw-telegramTelegram front end. Needs TELEGRAM_BOT_TOKEN and a numeric TELEGRAM_OWNER_ID; fails closed without them.
starclaw-serverHTTP API and small web console on 127.0.0.1:3000. Needs STARCLAW_API_KEY (16+ characters). No TLS.

Development

npm run build && npm test && npm run typecheck

The tests use a fake model and a fake payment rail. Nothing in the suite calls a real provider.

Watch the boundaries hold

The offline injection demo uses a scripted model and a fake payment rail. The sandbox, policy checks, approvals and audit verification are real.

git clone https://github.com/mnemopay/starclaw
cd starclaw
npm install
npm run build
node dist/cli.js sandbox build
npm run demo

Docker is recommended. Without it, the demo uses the weaker process permission layer. The demo does not prove that real models cannot be steered.
